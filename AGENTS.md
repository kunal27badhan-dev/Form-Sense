# AGENTS.md

## Project shape
- Flutter app in `lib/` with startup flow: `main.dart` → `splash_screen.dart` → auth (`login_page.dart` / `register_page.dart`) → `main_navigator.dart` / `home_page.dart`.
- Firebase is initialized at startup with `DefaultFirebaseOptions.currentPlatform`.
- A Flask ML backend exists in `backend/` with prediction routes and model artifacts.
- ML UI is split into module screens under `lib/screens/ml_modules/` and uses shared services/models/widgets.

## Read first
- `pubspec.yaml` for app dependencies (`video_player`, Firebase, `http`) and assets.
- `lib/main.dart` for app bootstrap and the actual home entry point.
- `lib/services/endpoints.dart`, `lib/services/api_service.dart`, `lib/models/request_models.dart` for API contracts.
- `lib/screens/ml_modules/*.dart` for Meal/Workout/Weight/Fitness feature UIs.
- `backend/app.py`, `backend/routes/*.py`, `backend/training/train_models.py`, `backend/utils/*.py`, `backend/dataset/dataset.csv`.

## Current conventions
- Navigation is mostly `Navigator.push` / `pushReplacement`, with route map entries in `main.dart` for dashboard + ML routes.
- `SplashScreen` plays `assets/videos/splash.mp4` with `video_player` and replaces itself with `LoginPage` when playback completes.
- `LoginPage` uses `FirebaseAuth.instance.signInWithEmailAndPassword`; `RegisterPage` creates Firebase auth users + mock Firestore profile data.
- `AuthBackground` layers `assets/images/bg_image.jpeg` under a translucent overlay; keep that stack order when changing auth screens.
- `HomePage` quick actions launch ML modules (`/ml/meal`, `/ml/workout`, `/ml/weight`, `/ml/fitness`).
- Backend response contract remains:
  - `result` (string/number)
  - `extra` (human-readable detail)
  - `confidence` (nullable float; usually for classifiers)
- Workout responses now surface real exercise names (derived from dataset metadata mapping).

## Integration notes
- `lib/firebase_options.dart` is generated by FlutterFire CLI; do not hand-edit it unless you are intentionally changing generated config.
- Linux is not configured in `DefaultFirebaseOptions.currentPlatform`; Android/iOS/macOS/web/windows are present.
- If Firebase project settings change, regenerate both Flutter options and platform config together so `firebase_options.dart`, `firebase.json`, and Android/iOS files stay aligned.
- Backend base URL strategy:
  - Android emulator: `http://10.0.2.2:5000`
  - iOS/web/windows: `http://127.0.0.1:5000`

## Workflow that matters here
- Use `flutter pub get` after dependency or asset changes.
- Use `flutter analyze` to catch issues; the repo follows `package:flutter_lints/flutter.yaml` via `analysis_options.yaml`.
- Use `flutter test`; `test/widget_test.dart` currently validates ML screen rendering.
- For Firebase updates, prefer `flutterfire configure` over manual edits to generated config files.
- Backend local workflow:
  - `python -m venv backend\.venv`
  - `backend\.venv\Scripts\python -m pip install -r backend\requirements.txt`
  - `backend\.venv\Scripts\python backend\training\train_models.py`
  - `backend\.venv\Scripts\python backend\app.py`

## Asset reminders
- Asset paths currently in use: `assets/videos/splash.mp4`, `assets/images/bg_image.jpeg`.
- `assets/images/logo.jpeg` is declared in `pubspec.yaml` but not referenced in the current UI.

## ML dataset and training rules
- Primary training source is `backend/dataset/dataset.csv`.
- Training does not overwrite an existing dataset file with synthetic data.
- Required target columns:
  - `meal_recommendation`
  - `workout_recommendation`
  - `predicted_weight`
  - `fitness_level_class`
- Optional enrichment columns:
  - `workout_exercises`
  - `meal_highlights`
  - `fitness_guidance`
- Training exports `metadata.pkl` used at runtime for practical output text (exercise lists, meal highlights, guidance).
